# 好友串门：口信版

每次拜访包含来访方、接待方、主人确认的口信、可选 HTTPS 链接，以及独立状态。访客只呈现口信，不自动调用模型、不读取接待方文件、不执行工具。桌面形象目前使用访客头像卡片。

## 桌面体验

桌面人物下方的「好友串门」可以查看邀请、接待访客和发起拜访。

1. 选择已建立关系的好友，填写口信及可选链接，确认后敲门。
2. 接待方点击「请进」或「婉拒」。请进后显示访客标记和口信。
3. 接待方可填写一句回复，点击「送客并带回回复」。双方拜访记录中可查看回复。
4. 来访方可取消邀请，或召回进行中的访客。

当前桌面是本地 Demo，两个角色由本机操作者管理，没有跨用户身份认证。它与云端无头 Client 尚未连接；不要把本机桌面预览当成已完成跨电脑桌面通信。已有双 Agent Demo 可以直接体验；新版单 Agent 空间需先有好友才能发起拜访。不会自动创建第二位主人或自动加好友。

## 云端接口与 Client

Relay 使用设备 Bearer 令牌识别操作人，不信任请求体提供的 from/actor。只有双方能查询这次拜访；双方必须已建立好友关系。

- `GET /v1/visits`：查询本设备的拜访、状态和回复。
- `POST /v1/visits`：`{to, note, url?, key}`，创建邀请。key 用于网络重试去重。
- `POST /v1/visits/action`：`{id, action, reply?}`；action 为 accept、decline、cancel 或 end。仅 end 可携带回复。

```sh
npm run client -- visit <好友设备ID> '我的项目上线了，周末来试试吗？'
npm run client -- visits
npm run client -- visit-action <拜访ID> accept
npm run client -- visit-action <拜访ID> end '恭喜！周末一起看看。'
```

每台电脑使用自己的 CLIENT_DATA_DIR。Client CLI 通过 visits 主动查询，不会自动弹出跨电脑访客窗口；本轮未更新 ECS，需要部署新版 Relay 后使用这些接口。

## 规则与恢复

- 邀请最多保留 24 小时；接受后最多停留 5 分钟。到期为 expired，不会自动重新发起。
- 同一方向的好友对最多有一个待处理或进行中的拜访；每位接待方同时只能接待一个访客。
- 接受和拒绝仅由接待方操作，取消或召回仅由来访方操作。
- 相同 key 和内容重复创建返回同一拜访；相同 key 不同内容被拒绝。重复接受不延长时限，重复送客不覆盖回复。
- 口信及回复各最多 1000 字符；链接最多 2000 字符，仅允许不带登录凭证的 HTTPS 地址，需手动点击才打开。
- 本地 Demo 将拜访写入现有状态数据库，并通过 SSE 同步。Relay 使用独立 visits 表，读取和变更在事务内完成；状态重启后恢复，到期状态在查询/操作时更新。
- 云端口信和回复与消息正文一样为明文存储。当前本地拜访记录保留在本机；云端已结束拜访按 7 天清理。
- 当前没有暂停接待开关、实时自由对话、模型生成口信、礼物、独立访客动画或端到端加密。

`npm test` 覆盖好友限制、角色权限、重复操作、并发接待限制、到期、取消、数据库恢复和第三方隔离。测试不会调用真实模型。
