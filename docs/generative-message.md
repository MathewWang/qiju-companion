# Generative Message

A 的 Agent 把一句话做成一件可以发送和重播的作品。A 先在自己的设备上预览，确认后发送。B 的 Agent 收到作品和文字摘要，可以交给本地播放器展示。首版把它作为普通消息的一种，串门可以是打开这份作品的场景。

第一条示例是桃桃送花庆祝项目上线。A 的 Agent 编排桃桃招手、花束升起、祝福浮现三个片段。A 预览后点发送，B 打开消息就看到同一段编排。无头 Client 可以查看文字摘要，并把场景交给其他播放器。

```json
{
  "type": "generative.message",
  "version": 1,
  "fallbackText": "桃桃送你一束花。恭喜上线！",
  "scene": {
    "durationMs": 3200,
    "cues": [
      {"atMs": 0, "kind": "character.clip", "asset": "taotao.wave.v1"},
      {"atMs": 600, "kind": "prop.show", "asset": "bouquet.v1", "motion": "rise"},
      {"atMs": 1200, "kind": "caption.show", "text": "恭喜上线！"}
    ]
  }
}
```

所有交互消息统一在 Web 容器里展示。聊天列表显示摘要和入口，打开后加载作品。动画、可点击贺卡和小互动共用这一入口。A 在发送前用同一个容器预览，B 打开后播放或操作。桌面端可以嵌入容器，Web 端可以直接承载，无头 Client 提供摘要和作品数据。

首版由可信的 Web 播放器读取场景 JSON。场景描述包含时间轴和版本化素材标识，按钮等交互由播放器按已支持的组件处理。素材随客户端安装，后续可以支持带内容哈希的素材包。如果以后支持 Agent 自带 HTML 和 JavaScript，把作品放进独立来源的沙箱 iframe，只通过受限消息接口与宿主通信。作品的数据和资源访问权限由宿主控制。

Relay 复用消息的好友鉴权、离线投递和去重，额外校验格式和大小。缺少素材或遇到未知版本时显示摘要。接收端播放无需调用模型。涉及回传的操作，例如点「收下」通知 A，由宿主提交对应事件，服务端校验消息参与者并去重。

涉及操纵 B 的本地角色时，先展示动作请求，等 B 同意后才让该角色参与。预先制作的双人短片可以作为独立作品播放。它和调用 B 的本地角色是两种权限。

第一版验证 A 的 Agent 生成场景 → A 预览确认 → Relay 投递 → B 播放及重播。先用送花和祝福字幕验证作品传递，再扩展素材和编排能力。本文为设计稿。
