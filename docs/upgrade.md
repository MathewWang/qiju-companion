# 桌面客户端升级

本次升级把聊天、好友、串门拆成三个简洁入口，并接上好友提问的主人确认和交流后的主动汇报。

## 升级范围

两台电脑都更新桌面客户端。阿里云 Relay 沿用目前已经部署的版本，本次无需修改云端数据库、域名或邀请码。不需要重新注册人物、不需要重新加好友；云端设备 ID、令牌和绑定保留。

默认所有新收到的好友问题先交给主人确认。这一版不自动判断哪些私人内容可以直接发送。主人可输入本次答复，或主动点「拟个回复」使用已授权近况生成草稿；草稿必须再次确认才能发送。没填授权近况时只允许直接填写本次答复，不调用模型猜测。点击「暂不提供」会发出固定的婉拒回复。

收到对方回复、发出主人确认的答复、发生处理失败时，助理把结果写入本机聊天并显示未读提示。收到的答复尽可能关联原始提问；旧版没有保存消息对应关系时，只展示收到的原文。通知用持久化键去重，重启不反复提醒。汇报直接使用实际结果，不额外调用模型改写。

## 让另一台电脑的 Codex 执行

> 帮我升级知交信使：https://github.com/MathewWang/qiju-companion 。先阅读 AGENTS.md、INSTALL.md 和 docs/upgrade.md。复用已有项目及 .data，不重新克隆覆盖、不重新注册、不复制另一台电脑的 config.json。先正常退出知交信使，并检查是否有独立的无头 Client 或本地服务占用；正常停止它们。退出后将整个 .data 备份到项目外的私有目录，再检查 Git 分支和本地修改。工作区干净且为 main 时用 git pull --ff-only origin main 更新，运行 npm run desktop:setup，再运行 npm run desktop。若有本地改动或分支分叉，先保留并说明，不执行 reset、clean 或自动覆盖。启动后确认原角色、聊天、好友和云端设备 ID 保留，检查聊天 / 好友 / 串门三个入口。不要为了验证而向真实好友发消息、调用模型或替我确认信息；我会手动做双机测试。

手动执行的主要命令（先退出应用和后台服务并备份资料）：

```sh
git status --short
git branch --show-current
git pull --ff-only origin main
npm run desktop:setup
npm run desktop
```

Electron 下载慢可使用：

```sh
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm run desktop:setup
```

不要同时启动桌面后台与 `node client/index.mjs run`。独立无头 CLI 仍保留原来的自动回复行为；本次主人确认和桌面汇报流程由桌面版启用。另一台只有桌面页面更新、后台没有重启时，不会获得新行为，必须完整退出再启动。

## 两机验收

1. 两端打开「好友」，确认原好友关系、基础资料和在线状态；这里没有直接发消息入口。
2. A 的主人在聊天中委托自己的助理向 B 了解一个测试问题。B 出现待确认提示，不会立即自动调用模型或回复。
3. B 点击人物，在聊天卡片输入本次答复，点「确认并发送」。B 收到已发送汇报，A 收到带对方回答的汇报。
4. 再测试「拟个回复」：先在设置中填可分享近况。生成草稿后 A 不会收到消息，B 确认后才发出。
5. B 不处理一条问题，退出并重启：待确认卡片仍在，同一提醒不会新增多份。
6. 串门仍需对方「请进」。链接和往来记录默认折叠，当前邀请与访客优先展示。

升级前已由旧客户端自动答复的消息不能撤回；新版可补出这些本机历史消息的汇报。等待确认期间，消息已经安全存入接收方本机 SQLite，云端已确认投递；请保留并备份 .data。

界面约定：聊天展示全部主人对话与助理汇报，不因待确认事项隐藏主人消息，也不只截取最近三条。Agent 间的发送回执和历史交流细节保存在本机，不放进主人聊天。好友页只展示基础资料和关系管理；切换聊天、好友、串门和设置时面板保持固定高度，内容内部滚动。

人物拖到显示器左半侧时，对话面板在人物右侧展开；拖到右半侧时在人物左侧展开。方向按照人物所在显示器判断，保持人物位置和面板尺寸，避免切换 tab 时跳动。

## 暖黑与香槟金界面

浮窗顶栏将名字和在线状态收在同一行，聊天输入框固定在底部。好友列表展示头像、名字、在线状态；已是好友时右侧小门可进入串门页，并预先选中该好友。串门通过头像选择接待方，写便笺后点击「敲门」；「链接」在便笺下方按需展开，往来记录移到右上角。加号返回好友页，不会创建虚构联系人。使用现有角色立绘裁切头像，预置形象和动作素材没有变化。
