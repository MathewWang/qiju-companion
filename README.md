# 知交信使

角色素材约定：所有新增可选形象必须同时提供透明立绘和配套动作图集。当前八位角色共用四列三行逐帧播放器，支持眨眼、招手、坐下及反向站起；`/?characters=1` 查看形象，`/?motion=1` 切换动作。素材规则见 AGENTS.md，生成记录见 docs/character-motion-collection.md。

连接每台电脑上的私人 Agent。云端只负责认证、好友关系和消息中转，无头 Client 在用户电脑上调用本机 Agent。

新的 Server / Client 已实现邀请制命令行版本：

- `npm run relay`：云端中转服务，默认监听 `127.0.0.1:4318`，需设置 `RELAY_INVITE_TOKEN`。
- `npm run client -- help`：本机无头 Client，支持登记、好友审批、发送、收件箱和后台运行。
- 使用独立 SQLite 数据库保存云端队列和本机记录；模型凭证留在用户电脑。

完整配置、双设备体验和 ECS 部署步骤见 [无头 Client 指南](docs/headless-client.md)。

新增「好友串门」口信版：好友敲门、手动请进、访客卡片、捎回回复、送客与召回。桌面本地体验与云端 CLI 使用相同状态规则，邀请 24 小时有效，接待最多 5 分钟；详见 [访客功能说明](docs/visits.md)。桌面与云端目前仍独立，新增接口尚未部署到 ECS。

当前桌面界面仍是独立的本机 Demo，尚未接入新中转服务。以下保留原 Demo 使用说明。

注册页已更新为单 Agent 流程：身份与名片 → 本地引擎 → 公开预览与创建。默认由主人审批好友，公开名片与一次真实模型连接验证分别征求确认。页面使用 `/api/register`，只创建一个本地 Agent；尚不创建云端账号或设备绑定。旧双角色批量接口仍兼容，下面的双角色体验说明及相关旧 UI 验收脚本属于历史 Demo 流程。

新版注册可在本地空数据空间预览：`COMPANION_DATA_DIR=/tmp/zhijiao-registration-preview PORT=4325 npm start`，访问 `http://127.0.0.1:4325/?register=1`。预览和填写表单不会调用模型；最终确认创建会调用一次。`npm test` 的单 Agent 注册测试使用隔离模拟 CLI，不消耗模型额度。

# 原本机 Demo 使用说明

本机体验的 Agent 角色工作室。独立于上层已有项目。

## 启动

本机已安装依赖后，可双击 `启动栖居.command` 打开桌面版。

要求 Node.js 22.13+（使用内置 SQLite）、已登录且可用的 Codex / OpenCode CLI。

```sh
git clone https://github.com/MathewWang/qiju-companion.git
cd qiju-companion
npm install
npm run build
npm start
```

打开 http://127.0.0.1:4317 。首次进入双 Agent 注册向导，完成后仅显示私人助理，点击显示最近消息，点“和我说说”展开输入框；历史聊天单独打开。角色/引擎管理实验室保留在 `/?studio=1`，不作为正常使用入口。另一个终端执行 `npm run desktop` 可打开桌面窗口和可拖动角色；已有本地服务时会复用。关闭历史窗口只隐藏窗口，桃桃继续留在桌面；从菜单栏 ✳ 选择“退出知交信使”才退出应用。手动启动的服务继续运行。

## 已实现

- 三步注册两位独立 Agent：主人、名字、两套动漫预制形象、公开名片、私有可分享近况、引擎与好友申请处理策略；完成前真实验证两套引擎。
- 真正调用本机 CLI。Codex exec JSON 与 OpenCode run JSON 实现相同适配契约，不通过 UI 自动化。
- 聊天、处理中状态、停止任务、超时与错误展示、暂停/恢复。
- 按主人称呼查找本机公开目录，持久化好友申请；收件方依据预授权接受或主人手动处理，接受后才可投递问题。
- 收件方暂停时消息进入 SQLite 持久收件箱，上线后按顺序处理；不会无限互聊。主人消息也有持久处理状态，服务重启后恢复未完成回复。
- 按需生成工作汇报，来源是实际聊天和好友记录。
- Electron 主窗口与透明可拖动人物，点击人物打开主窗口。

## 架构与扩展

`server/adapters.mjs` 的 `adapters` 注册表包含 command/args/env；`parseEvent` 把厂商输出映射成文本；`runAgent` 处理进程、超时和取消。增加引擎不需改变 UI 消息模型。上线产品可把 CLI 适配器换成 Codex app-server / OpenCode HTTP SDK，继续复用角色和通信层。

`server/index.mjs` 包含本地服务、消息调度、好友关系与 SQLite；`src` 是 React UI；`electron.cjs` 是可选桌面外壳。仅监听 127.0.0.1，校验 Host/Origin 与 JSON 内容类型。

角色身份独立于模型会话。Demo 每轮启动独立 CLI 执行，将最近 24 条当前会话记录作为上下文；完整记录持久保存。没有无限长记忆或自动压缩摘要。各好友会话不会收到主人私聊或其他好友的记录；主人私聊可参考最近好友交流，主人汇报可汇总两者。Codex 用临时会话、只读模式且不加载用户配置（本地认证仍沿用）；OpenCode 沿用供应商配置但禁止工具执行、外部插件和自动分享。本版仅用于信息交流，不开放文件操作、任意命令执行和外部发布。

`.data/registration-v2/companion.sqlite` 保存角色、申请、关系、消息、汇报；`.data/registration-v2/workspaces` 是独立工作目录。两者均被 git 忽略。模型调用仍会把当前对话发送给相应模型供应商，使用用户原有额度。平台不读取或上传 CLI 登录凭证。OpenCode 自己也可能持久化它的会话。

## 体验步骤

1. 启动服务和 Client，首次自动打开注册向导。默认桃桃属于马修、使用 OpenCode + GLM；小白属于黛比、使用 Codex。
2. 各自填写主人、公开简介、性格和允许分享的近况；从桃桃/小白两套系统形象中选择。留空的近况不会由模型编造。
3. 选择好友申请策略。默认预授权自动接受；取消后需在桌面设置的“Demo 体验身份”切换至接收方手动同意/拒绝。
4. 确认公开范围为本机名片目录，点击“验证连接并完成注册”，真实验证两次 CLI 调用，成功后回到桌面。
5. 点击桃桃，说“帮我联系黛比”。桃桃发现名片、发申请，只有对方同意才通知你可以开始提问。
6. 再问“黛比最近在干嘛？”。桃桃向好友发问并汇总回复。历史聊天可单独查看。

旧数据 `.data/companion.sqlite` 原样保留。新向导使用独立的 registration-v2 空间；后续重启恢复注册状态，不重复注册。可通过 COMPANION_DATA_DIR 指向不同空间。

本地现有数据不会随仓库上传；新克隆需要完成以上角色配置。

## Demo 边界

不是公网服务：没有真实主人注册/设备认证、跨电脑邀请链接、云端托管、端到端加密或开机自启动。本机角色均由当前操作者管理，主人称呼没有身份认证。名片目录只包含公开字段，但 /api/state 是本机管理视图，不能作为多租户隔离接口。桃桃、小白均采用生成的透明 PNG 预制立绘，搭配 CSS 轻微呼吸/摆动，不是完整动作包或 Live2D。素材与生成提示词见 docs/character-art.md。

支持主人在私聊中委托“帮我问小白……”：模型输出结构化发信动作，宿主校验已建立好友关系后真实投递；好友回复后自动生成给主人看的汇报。每次委托最多联系一位好友并完成一次问答，不自动循环。其他一般工作汇报仍由主人点击触发。尚未实现主动发起社交、定时巡检、主动汇报阈值或可靠跨设备执行租约。失败消息显示失败，不自动重试以免重复收费；可重新发送。停止时可能仍计入已经发生的模型用量。网络中断会保留本地记录，页面 SSE 自动重连。

UI 中「已安装」只表示 CLI 存在，成功回复才验证登录与模型可用性。CLI 版本和协议改变时需要适配测试。

## 轻量桌面交互与主人身份

默认主助理为桃桃（主人马修）；小白属于黛比，作为内部通信对象，正常界面不暴露其名字与引擎。联系人按 ownerName/ownerId 路由。问“你了解黛比最近在干嘛？”会在缺少已知近况时触发对黛比助理的询问，再由桃桃向马修汇报。没有可共享近况时如实说未知，不能把测试数据当成真实近况。设置内可修改自己的称呼及明确允许共享的近况；好友执行仅使用它自己显式允许共享的资料。

Electron 使用固定 620×540 透明画布（不超过屏幕工作区），默认人物位于右下角。点击后人物左移、右侧黑色聊天面板同步展开，消息气泡采用 Liquid Glass 风格；收起时反向过渡。动画使用 transform/opacity，避免原生窗口缩放卡顿；透明空白区域鼠标穿透。历史窗口按需打开，关闭后隐藏。默认主助理为首次创建的角色；仅设置内的 Demo 身份切换可以换到另一位主人以测试手动接受申请。

`tests/delegation.mjs` 在隔离临时数据库和 4321 端口验证主人姓名路由、真实 GLM→Codex→GLM 链路、没有公开内部Agent名称、收起/气泡/输入/设置联系人/历史交互；示例“读书会”仅为隔离测试fixture，未写入用户Demo数据。

## 双人物桌面
注册后同时打开桃桃与小白两个独立透明窗口，可各自拖动。人物下方显示主人、在线/处理中/休息状态、好友数量及待处理申请入口。点击任一人物查看其最近消息与输入框，设置可查看引擎、名片和处理好友申请。每个窗口通过 agent ID 固定角色，历史窗口、草稿及已读状态独立；不会跟随全局体验身份切换。菜单栏“显示所有助理”可重新显示两位人物。浏览器单页可通过 `?agent=<id>` 查看指定角色。
`node tests/dual-desktop.mjs` 在已有双角色注册的本机运行 Electron 冒烟测试，不发送模型请求；应先退出正在运行的桌面应用。
